语言基础与面向对象

言羽2026/9/8大约 16 分钟Java基础面向对象

Java 只有值传递

结论：调用方法时，实参的值被复制给形参。基本类型复制数值，对象类型复制引用值，不是复制整个对象。

易错点：方法可以通过复制的引用修改同一个对象，但重新给形参赋值不会改变调用者变量指向的对象。

import java.util.ArrayList;
import java.util.List;

public class PassByValue {
    static void change(List<String> values) {
        values.add("Java");
        values = new ArrayList<>();
        values.add("MySQL");
    }

    public static void main(String[] args) {
        List<String> topics = new ArrayList<>();
        change(topics);
        System.out.println(topics);
    }
}

预期结果：输出 [Java]。保存为 PassByValue.java 后可用 javac PassByValue.java 和 java PassByValue 验证。

== 与 equals

结论：对引用类型，== 比较是否指向同一个对象；equals() 的语义由类决定。Object 默认按身份比较，String 重写后按字符序列比较。

易错点：不能把所有类的 equals() 都理解成“比较内容”。重写 equals() 时通常也必须重写 hashCode()，保证相等对象有相同哈希值。

重载与重写

结论：重载是同名方法的参数列表不同，主要在编译期选择；重写是子类提供父类实例方法的实现，运行时根据实际对象进行动态分派。

易错点：仅改变返回类型不能构成重载。静态方法属于隐藏，不属于实例方法的多态重写。

final 关键字与不可变性

结论：final 修饰类表示该类不可被继承；String 和 StringBuffer 均为 final 类，HashMap 和 Hashtable 则不是。

原因：

  • final class 禁止派生，旨在保护类的核心行为不被篡改，多见于不可变类或线程安全类。
  • String 的 final 设计保障了不可变性，使字符串常量池、哈希码缓存和类加载安全成为可能。
  • StringBuffer 的 final 设计防止子类覆盖其同步方法，确保线程安全语义不被破坏。

典型 final 类：

  • String、StringBuilder、StringBuffer
  • 基本类型包装类：Integer、Long、Double 等
  • 枚举类型（enum）隐式为 final

易错点：

  • final 类 ≠ 不可变对象：StringBuffer 是 final 类但其对象内容可变（通过 append 等方法）；String 则是 final + 不可变。
  • 线程安全类不一定是 final 类（如 Hashtable、Vector），final 类也不一定线程安全（Integer 虽不可变但无同步需求）。
  • 判断 final 类应以源码声明为准，不能凭“常见用法”或“是否线程安全”推断。

继承中的构造器调用与方法重写

结论：子类构造器执行前隐式调用父类无参构造器；重写方法的调用由运行时实际类型决定（动态绑定），而非声明类型。

构造器执行顺序：

  • 子类构造器第一条语句默认为 super()，若父类无可访问的无参构造器则编译报错。
  • 执行顺序始终为：父类构造器 → 子类构造器。

方法调用规则：

  • 对于被重写的实例方法，调用哪个版本取决于对象的实际类型（运行时类型），而非引用变量的声明类型。
  • static 方法、private 方法和 final 方法不参与动态绑定，由编译时类型决定。

易错点：

  • 构造器输出与方法输出需分开判断：先确定构造顺序，再根据实际类型确定方法版本。
  • 本题变量声明为 A a，但 new B() 的实际类型是 B，因此调用的是 B 的 method()，而非 a 的声明类型 A 的版本。

main 方法的命令行参数

结论：main(String[] args) 中的 args 数组接收命令行中类名之后的所有参数，按顺序从 args[0] 开始存储。java 命令和类名本身不进入数组。

规则：

  • 执行 java <类名> [参数1] [参数2] ...，类名后的每个空格分隔项依次对应 args[0]、args[1]...
  • 参数个数可变，未传参时 args.length == 0，直接访问 args[0] 会抛 ArrayIndexOutOfBoundsException。
  • 所有参数均为字符串类型，数字型参数需手动解析。

易错点：

  • java 命令和类名不属于参数，不要将其计入 args。
  • 参数中包含空格时需用双引号包裹整体，如 "hello world"，否则会被拆成两个独立参数。
  • args 索引从 0 开始，第一个参数为 args[0]。

类与实例的初始化顺序

结论：Java 类在首次加载时执行静态代码块，实例化时执行普通代码块和构造器。完整顺序为：父类静态块 → 子类静态块 → 父类普通块 → 父类构造器 → 子类普通块 → 子类构造器。

执行顺序说明：

  1. 父类静态代码块（类加载时）
  2. 子类静态代码块（类加载时）
  3. 父类普通代码块（实例化时，在构造器前）
  4. 父类构造器
  5. 子类普通代码块（实例化时，在构造器前）
  6. 子类构造器

关键规则：

  • 静态优先：静态代码块在类加载阶段执行，先于任何实例化操作，且只执行一次。
  • 父类优先：无论静态块还是普通块，父类内容始终先于子类执行。
  • 普通块优先于构造器：普通代码块在构造器执行前运行，可用于统一初始化逻辑。

易错点：

  • 静态代码块执行条件：只有首次加载类时执行，后续 new 或访问静态成员不会再触发。
  • 普通代码块每次实例化都会执行，与构造器执行次数一致。
  • 若父类构造器显式调用 super(...)，顺序仍遵循“父类普通块 → 父类构造器”的原则。
  • 静态块内部不能直接访问实例变量（非静态字段），因为此时实例尚未创建。

静态成员与实例成员的访问规则

结论：静态成员（static 修饰的变量和方法）属于类，可以通过类名直接访问；实例成员（非 static 的变量和方法）属于对象，必须通过对象引用访问，不能通过类名调用。

访问方式对比：

成员类型访问方式示例（基于定义 static String s; 和 void method1(){}）
静态变量类名.变量名 或 对象.变量名（不推荐）A.s 或 a.s，推荐 A.s
静态方法类名.方法名() 或 对象.方法名()（不推荐）A.method2() 或 a.method2()，推荐 A.method2()
实例变量对象.变量名，不能用类名a.i，不能用 A.i
实例方法对象.方法名()，不能用类名a.method1()，不能用 A.method1()

原因：

  • 静态成员随类加载而初始化，在内存中只有一份，不依赖任何实例存在。
  • 实例成员随对象创建而分配，每个对象有独立副本（或独立的 this 绑定），调用时必须明确所属对象。

易错点：

  • 实例方法中可以直接访问静态成员（因为静态成员先于对象存在，且全局唯一）。
  • 静态方法中不能直接访问实例成员（因为调用静态方法时可能没有任何实例存在），必须通过对象引用间接访问。
  • 通过对象引用访问静态成员合法但违反编码规范，易造成误解，应直接用类名访问。

继承中的成员访问：父类无法访问子类新增成员

结论：子类继承父类的 public 和 protected 成员（以及同包默认成员），子类对象可访问父类中的公开方法。但父类无法访问子类新增的成员变量或方法，因为继承是单向的。

规则说明：

  • 子类对象可以调用父类中定义的 public 或 protected 方法（如 B 对象可调用 A 的 geta()）。
  • 父类对象不能调用子类中新增的方法（如 A 对象不能调用 B 的 setb()），因为父类根本没有定义该方法。
  • 即使父类引用指向子类对象（如 A a = new B();），编译时类型仍是 A，只能调用 A 中声明的方法；若要调用 B 特有方法，必须向下转型：((B) a).setb(1.0);。

易错点：

  • 不要混淆“对象实际类型”与“引用声明类型”：父类引用指向子类对象时，可调用的方法由引用类型决定，而非实际对象类型。
  • 继承方向不可逆：子类继承父类，但父类对子类新增内容一无所知。

方法重载与重写的区别

结论：重载（Overload）是同一类中多个同名方法参数不同；重写（Override）是子类重新定义父类方法，参数必须相同，返回值须相同或其子类型。

重载规则：

  • 发生位置：同一个类中。
  • 方法名相同，参数列表必须不同（类型、个数、顺序至少一项不同）。
  • 返回值类型无要求，可相同可不同。
  • 访问修饰符、异常声明无限制。
  • 用途：提供多个版本的方法以处理不同类型的参数。

重写规则：

  • 发生位置：父子继承关系中（子类覆盖父类方法）。
  • 方法名、参数列表必须完全相同。
  • 返回值：必须与父类方法返回值相同，或是其子类型（协变返回类型）。
  • 访问修饰符：子类方法的访问权限不能比父类更严格（如父类 public 不能改为 private）。
  • 异常声明：子类不能抛出比父类更宽泛的检查型异常（可抛出更少的异常）。
  • 用途：实现运行时多态，子类提供父类方法的具体实现或扩展。

易错点：

  • 仅返回值不同而参数相同的两个方法不构成重载，也不能编译通过。
  • @Override 注解可帮助编译器检查是否正确重写，建议显式标注。
  • 重写发生在运行时（动态绑定），重载发生在编译时（静态绑定）。

变量类型与初始化对比

结论：实例变量和类变量（静态变量）有默认值；局部变量没有默认值，必须显式初始化后才能使用；final 变量必须赋值一次，之后不可变。

各类变量特性：

  • 实例变量（非 static 成员变量）：定义在类中方法外，有默认值，每个对象独立存储。
  • 类变量（static 成员变量）：定义在类中方法外，类加载时初始化，有默认值，所有实例共享。
  • 局部变量：定义在方法或代码块内，无默认值，必须在首次使用前显式赋值。
  • final 变量：一经赋值不可修改。成员 final 可在声明时或构造器中赋值（若未赋初值）；局部 final 在使用前必须赋值一次。

默认值速查：

  • 数值类型（int, long, float, double 等）：0 / 0.0
  • 布尔类型（boolean）：false
  • 引用类型（String, Object, 数组等）：null
  • char：'\u0000'（空字符）

易错点：

  • 成员变量（实例/静态）不初始化不会报错，编译器赋默认值。
  • 局部变量不初始化直接使用会导致编译错误，而非运行时异常。
  • final 修饰的成员变量若未在声明时赋值，必须在所有构造器中完成赋值（或构造器链中确保赋值）。

按位异或（^）运算符

结论：^ 是 Java 中的按位异或运算符，用于对整数类型进行按位比较，相同位结果为 0，不同位结果为 1。14 ^ 3 的计算结果为 13。

按位异或规则：

  • 两操作数对应位相同 → 结果为 0
  • 两操作数对应位不同 → 结果为 1

计算过程：

  14 = 1110
   3 = 0011
  XOR = 1101 = 13（十进制）

常见误区：

  • ^ 不是幂运算符。Java 中幂运算需使用 Math.pow(14, 3)。
  • 按位异或仅适用于整数类型（int、long、short、byte、char）。

其他用途：

  • 常用于简单的加密/解密（对称异或）。
  • 用于交换两个变量的值（不推荐在实际代码中使用）。
  • 用于布尔值的异或逻辑（^ 也可用于 boolean，作为逻辑异或）。

易错点：

  • 不要将 ^（按位异或）与 &&（逻辑与）、||（逻辑或）混淆。
  • ^ 对 boolean 类型同样适用（逻辑异或），但实际开发中较少使用。

引用传递与成员变量默认值

结论：引用类型（如 Byte、String、Object）的成员变量默认值为 null，而非基本类型的对应默认值（如 int 默认 0）。方法参数传递的是对象引用，对对象内部属性的修改会影响所有指向该对象的引用变量。

成员变量默认值规则：

  • 基本类型成员变量有默认值（int → 0，boolean → false，char → '\u0000'）。
  • 引用类型成员变量（包括数组、类、接口、包装类如 Byte）默认值为 null。

对象引用传递规则：

  • Java 方法参数传递的是对象的引用（地址），而非对象副本。
  • 方法内通过参数引用修改对象属性，会影响调用者持有的同一对象。
  • 多个引用变量可以指向同一个对象，任一变量修改属性，其他变量感知变化。

示例分析：

Two t = new Two();      // t.x = null
Two t2 = fix(t);        // t 和 t2 指向同一对象
// fix 内修改 tt.x = 42 → t.x = 42, t2.x = 42

易错点：

  • Byte 是引用类型，默认值为 null，不要误认为其有基本类型 byte 的默认值 0。
  • 参数传递是“引用值传递”——传递的是引用的副本，但该副本指向同一对象，因此对象内容可被修改。
  • 区分“引用本身不可变”与“对象内容可变”：方法内可修改对象属性，但不能改变调用者引用指向的对象（除非通过返回值重新赋值）。

类型转换与精度丢失

结论：从浮点类型（float/double）强制转换为整数类型（int/long）时，小数部分被截断，可能产生精度丢失。从低精度向高精度转换（如 int → double）通常不会丢失精度，但需注意浮点数无法精确表示大整数时也可能有误差。

常见精度丢失场景：

  • 浮点 → 整数：使用强制转换 (int) d，小数部分直接截断（非四舍五入），可能丢失精度。
  • 大整数 → 浮点：当整数超过浮点数的有效位数时（如 float f = 16777217;），低精度浮点无法精确表示，产生舍入误差。
  • 高精度整数 → 低精度整数：如 long 转 int，可能溢出。

不会产生精度丢失的转换：

  • 整数 → 浮点数（如 double d = 10;），只要在浮点数精确表示范围内。
  • 低精度整数 → 高精度整数（如 byte → int）。
  • 同一精度类型间的转换（如 int → long）。

易错点：

  • 强制转换 (int) 8846.0 虽然小数部分为 0，但从类型角度仍属于“浮点转整数”操作，存在精度丢失的可能性。
  • 浮点数转整数时不会四舍五入，而是直接截断（(int) 3.9 结果为 3）。
  • float 类型的有效数字约为 7 位，超出部分可能无法精确表示。

Object 类常用方法

结论：Object 是所有 Java 类的根类，定义了所有对象通用的方法，包括 toString()、equals()、hashCode()、wait()、notify() 等。finally 不是 Object 类的方法，而是异常处理关键字。

Object 类核心方法：

方法说明
toString()返回对象字符串表示，可重写用于打印有意义内容
equals(Object obj)比较对象逻辑相等性，默认等价于 ==
hashCode()返回哈希码，与 equals() 一致（重写时需一起重写）
getClass()返回对象的运行时 Class 对象
wait() / wait(long)线程等待，释放锁，需在同步块中调用
notify() / notifyAll()唤醒等待该对象监视器的线程
clone()创建并返回对象的浅拷贝（需实现 Cloneable）
finalize()GC 前回调（已废弃，Java 9+ 标记为 deprecated）

常见误区：

  • finally 是异常处理的关键字（代码块），不是 Object 的方法。
  • finalize() 是 Object 的方法，但已被废弃，不推荐使用。
  • wait() 和 notify() 必须在 synchronized 块中调用，否则抛出 IllegalMonitorStateException。

Java 访问修饰符与 protected 权限

结论：protected 修饰的成员可被同一包中的所有类访问，也可被不同包中的子类访问。因此，同一包中的非子类也能访问 protected 方法。

访问修饰符适用范围：

修饰符同一类同一包不同包·子类任何位置
private✅❌❌❌
默认（无修饰符）✅✅❌❌
protected✅✅✅❌
public✅✅✅✅

关键理解：

  • protected = 包访问（package-private）+ 子类继承访问，两者并存。
  • 同一包中的任意类都可访问 protected 成员，不要求继承关系。
  • 不同包中只有子类可访问（通过继承），非子类不能访问。

常见误区：

  • 不要认为 protected 只对子类可见——它还包括同一包中的所有类。
  • 不同包中的非子类即使是同一父类也无权访问 protected 成员。
  • 子类在不同包中访问父类 protected 成员时，仅能通过继承访问（如 super.method() 或子类实例），不能通过父类实例访问。

包装类（Wrapper Class）

结论：Java 为 8 种基本数据类型提供了对应的包装类（Byte、Short、Integer、Long、Float、Double、Character、Boolean），用于将基本类型值封装为对象。String 不是包装类，是独立的引用类型。

基本类型与包装类对照：

基本类型包装类
byteByte
shortShort
intInteger
longLong
floatFloat
doubleDouble
charCharacter
booleanBoolean

包装类的作用：

  • 集合框架（如 ArrayList<Integer>）中存储基本类型值。
  • 提供类型转换方法（Integer.parseInt("123")、Double.valueOf("3.14")）。
  • 作为泛型的类型参数（泛型不支持基本类型）。
  • 提供常量和方法（Integer.MAX_VALUE、Character.isDigit()）。

自动装箱与拆箱（Java 5+） ：

  • 自动装箱：Integer i = 10; 等价于 Integer i = Integer.valueOf(10);
  • 自动拆箱：int n = i; 等价于 int n = i.intValue();

易错点：

  • String 不是包装类，虽然它常与基本类型转换一起使用。
  • 包装类是不可变对象，每次运算都会创建新对象。
  • 包装类比较时，值相同但对象不同时 == 返回 false，应使用 equals() 比较值（但 -128 ~ 127 范围内 Integer 使用缓存，== 可能返回 true，这一行为容易造成混淆）。

密封类（sealed class）与子类修饰符

结论：密封类（sealed class）的直接子类必须声明为 final、sealed 或 non-sealed 之一，以明确继承策略。abstract sealed 组合也是合法的，表示子类既是抽象的，又继续限制自身的子类范围。

sealed class 声明规则：

  • 父类使用 sealed 修饰，并用 permits 列出允许的直接子类。
  • 所有 permits 中列出的子类必须选择一种继承策略：
修饰符含义
final终止继承链，此类不能再有子类
sealed继续限制继承，需指定自己的 permits 列表
non-sealed解除密封限制，任何类都可继承（恢复普通继承）

附加说明：

  • 子类可以与 abstract 组合，如 abstract sealed 或 abstract non-sealed。
  • 单独的 abstract 不满足密封类子类的声明要求，必须配合 sealed 或 non-sealed。

示例：

sealed class Shape permits Circle, Rectangle, Triangle {}

final class Circle extends Shape {}           // 终止继承
sealed class Rectangle extends Shape permits Square {}  // 继续限制
non-sealed class Triangle extends Shape {}    // 开放继承

版本说明：sealed classes 是 Java 17 正式特性（JEP 409），需 Java 17+ 支持。
