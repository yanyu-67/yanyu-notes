## 适用场景

Git 适合保存笔记的修改历史，比较订正前后的结论，并在需要时定位某次变更。远程仓库还能提供异地副本，但 Git 本身不等于已经完成远程备份。

## 工作区、暂存区与提交

**结论**：工作区保存当前文件，暂存区保存下一次提交准备包含的内容，提交记录形成可追溯的版本。

```bash
git status --short
git diff
git diff --cached
```

**前提**：在已初始化的 Git 仓库中运行。当前知识库交付时不自动执行 `git init`、创建分支或提交；是否启用版本管理由仓库所有者决定。

## 日常记录习惯

完成一组相关知识点的补充后，先检查改动，再只暂存本次相关文件。提交说明写清修正了什么，例如“补充 ArrayList 容量与长度区别”。

**易错点**：`git add` 后再次编辑文件，新编辑内容不会自动进入已经暂存的版本。提交前同时检查工作区和暂存区。

## 不应进入版本库的内容

依赖目录、构建产物、缓存和密钥不应作为知识正文提交。本项目提供忽略规则；截图及日志发布前仍需自行检查是否包含个人信息、令牌或内部服务地址。
