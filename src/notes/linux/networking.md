## 地址可达不等于服务可用

**结论**：`ping` 通常用于 ICMP 连通性诊断，成功不代表目标 TCP 端口开放，也不代表 HTTP 服务正常；失败也可能仅是 ICMP 被过滤。

```bash
ip addr
ip route
ss -lnt
```

**易错点**：监听 `127.0.0.1` 的服务通常不能被其他机器直接访问。监听所有接口还需要结合防火墙及网络边界评估，不应为排错随意暴露服务。

## DNS、TCP 与 HTTP 分别检查

```bash
getent hosts example.com
curl -I --connect-timeout 5 --max-time 10 https://example.com
```

**结论**：第一步检查名称解析，第二步尝试建立连接并获取响应头。输出状态码只能说明该次请求结果，不能代替业务层校验。

**易错点**：`curl -I` 发送 HEAD 请求，某些服务不支持；这时应使用实际业务请求方法验证，而不是直接判定服务不可用。

## 实践记录的最小信息

记录时间、客户端位置、目标域名及端口、执行命令和原始错误。相同命令在服务器本机与外部客户端上的结果差异，能帮助区分监听配置、网络路径和应用故障。
