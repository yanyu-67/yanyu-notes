## ACID 分别保证什么

| 特性 | 含义 |
| --- | --- |
| 原子性 | 一组操作作为整体提交或回滚 |
| 一致性 | 事务前后满足定义的数据约束和业务规则 |
| 隔离性 | 控制并发事务之间相互可见的程度 |
| 持久性 | 已提交的数据在相应故障模型下可恢复 |

**易错点**：数据库不会自动理解所有业务规则，例如转账金额必须为正仍需要业务代码或约束保证。

## 默认隔离级别与读方式

**结论**：MySQL InnoDB 的默认隔离级别是可重复读，但实际实例或会话可能修改过。普通一致性读与 `SELECT ... FOR UPDATE` 等锁定读的行为不同。

```sql
SELECT @@transaction_isolation, @@autocommit;
```

**易错点**：不能仅凭“可重复读”就推导所有查询永远读取同一个版本。隔离级别、是否锁定读及快照建立时机都影响结果。

## 行锁与索引访问路径

**结论**：InnoDB 行级锁主要加在索引记录上，可重复读下某些范围访问还涉及间隙锁或临键锁，以限制相应范围内的并发插入。

**易错点**：“WHERE 中使用主键字段”不等于永远只锁一行，范围条件和实际访问路径会影响锁范围。事务应尽量短，并对死锁失败设计合理重试。

::: tip 练习方法
使用两个独立数据库会话做并发实验，分别记录隔离级别、SQL 顺序、阻塞位置与提交时间。仅在同一个会话依次执行 SQL 无法重现真实的并发可见性。
:::
