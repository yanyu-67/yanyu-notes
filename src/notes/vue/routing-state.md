## route 与 router

**结论**：Vue Router 4 的 `useRoute()` 获取当前路由信息，`useRouter()` 获取导航操作实例。前者用于读取参数，后者用于 `push()`、`replace()` 等操作。

**易错点**：同一路由组件只改变参数时可能被复用，不应假设每次参数变化都会重新执行挂载钩子。需要侦听相关参数变化。

## History 模式需要服务器配合

**结论**：客户端导航与直接刷新路径是两种请求流程。普通 SPA 使用 HTML5 History 模式时，服务器通常需要把未命中的前端路由回退到入口 HTML。

**易错点**：VuePress 会预渲染文档路径，部署时应正确提供对应的静态 HTML；不要直接照搬普通 SPA 的回退规则，掩盖真实 404 或忽略子路径配置。

## 状态应该放在哪里

| 状态类型 | 优先位置 |
| --- | --- |
| 单个弹窗是否展开 | 当前组件 |
| 父子组件共同使用的输入 | 最近的共同父组件 |
| 可分享的筛选条件、分页 | URL 参数 |
| 跨页面共享的登录状态等 | 明确设计的共享状态或 Pinia |

**易错点**：响应式状态不等于持久化状态，刷新页面后可能丢失。浏览器存储也不是敏感数据的安全保险箱，权限必须由服务端校验。

## 实践：刷新与导航分别验证

记录同一个页面通过站内点击、复制链接新开标签、直接刷新三种方式访问的结果。如果只有刷新失败，应先排查部署路径和服务器静态文件规则。
