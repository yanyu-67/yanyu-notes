## Java 只有值传递

**结论**：调用方法时，实参的值被复制给形参。基本类型复制数值，对象类型复制引用值，不是复制整个对象。

**易错点**：方法可以通过复制的引用修改同一个对象，但重新给形参赋值不会改变调用者变量指向的对象。

```java
import java.util.ArrayList;
import java.util.List;

public class PassByValue {
    static void change(List<String> values) {
        values.add("Java");
        values = new ArrayList<>();
        values.add("MySQL");
    }

    public static void main(String[] args) {
        List<String> topics = new ArrayList<>();
        change(topics);
        System.out.println(topics);
    }
}
```

**预期结果**：输出 `[Java]`。保存为 `PassByValue.java` 后可用 `javac PassByValue.java` 和 `java PassByValue` 验证。

## == 与 equals

**结论**：对引用类型，`==` 比较是否指向同一个对象；`equals()` 的语义由类决定。`Object` 默认按身份比较，`String` 重写后按字符序列比较。

**易错点**：不能把所有类的 `equals()` 都理解成“比较内容”。重写 `equals()` 时通常也必须重写 `hashCode()`，保证相等对象有相同哈希值。

## 重载与重写

**结论**：重载是同名方法的参数列表不同，主要在编译期选择；重写是子类提供父类实例方法的实现，运行时根据实际对象进行动态分派。

**易错点**：仅改变返回类型不能构成重载。静态方法属于隐藏，不属于实例方法的多态重写。

## final 关键字与不可变性

**结论**：`final` 修饰类表示该类不可被继承；`String` 和 `StringBuffer` 均为 final 类，`HashMap` 和 `Hashtable` 则不是。

**原因**：
- `final class` 禁止派生，旨在保护类的核心行为不被篡改，多见于不可变类或线程安全类。
- `String` 的 final 设计保障了不可变性，使字符串常量池、哈希码缓存和类加载安全成为可能。
- `StringBuffer` 的 final 设计防止子类覆盖其同步方法，确保线程安全语义不被破坏。

**典型 final 类**：
- `String`、`StringBuilder`、`StringBuffer`
- 基本类型包装类：`Integer`、`Long`、`Double` 等
- 枚举类型（`enum`）隐式为 final

**易错点**：
- final 类 ≠ 不可变对象：`StringBuffer` 是 final 类但其对象内容可变（通过 `append` 等方法）；`String` 则是 final + 不可变。
- 线程安全类不一定是 final 类（如 `Hashtable`、`Vector`），final 类也不一定线程安全（`Integer` 虽不可变但无同步需求）。
- 判断 final 类应以源码声明为准，不能凭“常见用法”或“是否线程安全”推断。


## 继承中的构造器调用与方法重写

**结论**：子类构造器执行前隐式调用父类无参构造器；重写方法的调用由运行时实际类型决定（动态绑定），而非声明类型。

**构造器执行顺序**：
- 子类构造器第一条语句默认为 `super()`，若父类无可访问的无参构造器则编译报错。
- 执行顺序始终为：父类构造器 → 子类构造器。

**方法调用规则**：
- 对于被重写的实例方法，调用哪个版本取决于对象的实际类型（运行时类型），而非引用变量的声明类型。
- `static` 方法、`private` 方法和 `final` 方法不参与动态绑定，由编译时类型决定。

**易错点**：
- 构造器输出与方法输出需分开判断：先确定构造顺序，再根据实际类型确定方法版本。
- 本题变量声明为 `A a`，但 `new B()` 的实际类型是 `B`，因此调用的是 B 的 `method()`，而非 `a` 的声明类型 A 的版本。

## main 方法的命令行参数

**结论**：`main(String[] args)` 中的 `args` 数组接收命令行中类名之后的所有参数，按顺序从 `args[0]` 开始存储。`java` 命令和类名本身不进入数组。

**规则**：
- 执行 `java <类名> [参数1] [参数2] ...`，类名后的每个空格分隔项依次对应 `args[0]`、`args[1]`...
- 参数个数可变，未传参时 `args.length == 0`，直接访问 `args[0]` 会抛 `ArrayIndexOutOfBoundsException`。
- 所有参数均为字符串类型，数字型参数需手动解析。

**易错点**：
- `java` 命令和类名不属于参数，不要将其计入 `args`。
- 参数中包含空格时需用双引号包裹整体，如 `"hello world"`，否则会被拆成两个独立参数。
- `args` 索引从 0 开始，第一个参数为 `args[0]`。

## 类与实例的初始化顺序

**结论**：Java 类在首次加载时执行静态代码块，实例化时执行普通代码块和构造器。完整顺序为：父类静态块 → 子类静态块 → 父类普通块 → 父类构造器 → 子类普通块 → 子类构造器。

**执行顺序说明**：
1. 父类静态代码块（类加载时）
2. 子类静态代码块（类加载时）
3. 父类普通代码块（实例化时，在构造器前）
4. 父类构造器
5. 子类普通代码块（实例化时，在构造器前）
6. 子类构造器

**关键规则**：
- **静态优先**：静态代码块在类加载阶段执行，先于任何实例化操作，且只执行一次。
- **父类优先**：无论静态块还是普通块，父类内容始终先于子类执行。
- **普通块优先于构造器**：普通代码块在构造器执行前运行，可用于统一初始化逻辑。

**易错点**：
- 静态代码块执行条件：只有首次加载类时执行，后续 `new` 或访问静态成员不会再触发。
- 普通代码块每次实例化都会执行，与构造器执行次数一致。
- 若父类构造器显式调用 `super(...)`，顺序仍遵循“父类普通块 → 父类构造器”的原则。
- 静态块内部不能直接访问实例变量（非静态字段），因为此时实例尚未创建。

## 静态成员与实例成员的访问规则

**结论**：静态成员（`static` 修饰的变量和方法）属于类，可以通过类名直接访问；实例成员（非 `static` 的变量和方法）属于对象，必须通过对象引用访问，不能通过类名调用。

**访问方式对比**：

| 成员类型 | 访问方式 | 示例（基于定义 `static String s;` 和 `void method1(){}`） |
|---------|---------|------------------------------------------------|
| 静态变量 | `类名.变量名` 或 `对象.变量名`（不推荐） | `A.s` 或 `a.s`，推荐 `A.s` |
| 静态方法 | `类名.方法名()` 或 `对象.方法名()`（不推荐） | `A.method2()` 或 `a.method2()`，推荐 `A.method2()` |
| 实例变量 | `对象.变量名`，不能用类名 | `a.i`，不能用 `A.i` |
| 实例方法 | `对象.方法名()`，不能用类名 | `a.method1()`，不能用 `A.method1()` |

**原因**：
- 静态成员随类加载而初始化，在内存中只有一份，不依赖任何实例存在。
- 实例成员随对象创建而分配，每个对象有独立副本（或独立的 `this` 绑定），调用时必须明确所属对象。

**易错点**：
- 实例方法中可以直接访问静态成员（因为静态成员先于对象存在，且全局唯一）。
- 静态方法中不能直接访问实例成员（因为调用静态方法时可能没有任何实例存在），必须通过对象引用间接访问。
- 通过对象引用访问静态成员合法但违反编码规范，易造成误解，应直接用类名访问。

## 继承中的成员访问：父类无法访问子类新增成员

**结论**：子类继承父类的 `public` 和 `protected` 成员（以及同包默认成员），子类对象可访问父类中的公开方法。但父类无法访问子类新增的成员变量或方法，因为继承是单向的。

**规则说明**：
- 子类对象可以调用父类中定义的 `public` 或 `protected` 方法（如 `B` 对象可调用 A 的 `geta()`）。
- 父类对象不能调用子类中新增的方法（如 A 对象不能调用 B 的 `setb()`），因为父类根本没有定义该方法。
- 即使父类引用指向子类对象（如 `A a = new B();`），编译时类型仍是 A，只能调用 A 中声明的方法；若要调用 B 特有方法，必须向下转型：`((B) a).setb(1.0);`。

**易错点**：
- 不要混淆“对象实际类型”与“引用声明类型”：父类引用指向子类对象时，可调用的方法由**引用类型**决定，而非实际对象类型。
- 继承方向不可逆：子类继承父类，但父类对子类新增内容一无所知。

## 方法重载与重写的区别

**结论**：重载（Overload）是同一类中多个同名方法参数不同；重写（Override）是子类重新定义父类方法，参数必须相同，返回值须相同或其子类型。

**重载规则**：
- 发生位置：同一个类中。
- 方法名相同，**参数列表必须不同**（类型、个数、顺序至少一项不同）。
- 返回值类型**无要求**，可相同可不同。
- 访问修饰符、异常声明无限制。
- 用途：提供多个版本的方法以处理不同类型的参数。

**重写规则**：
- 发生位置：父子继承关系中（子类覆盖父类方法）。
- 方法名、参数列表**必须完全相同**。
- 返回值：必须与父类方法返回值相同，或是其**子类型**（协变返回类型）。
- 访问修饰符：子类方法的访问权限不能比父类更严格（如父类 `public` 不能改为 `private`）。
- 异常声明：子类不能抛出比父类更宽泛的检查型异常（可抛出更少的异常）。
- 用途：实现运行时多态，子类提供父类方法的具体实现或扩展。

**易错点**：
- 仅返回值不同而参数相同的两个方法不构成重载，也不能编译通过。
- `@Override` 注解可帮助编译器检查是否正确重写，建议显式标注。
- 重写发生在运行时（动态绑定），重载发生在编译时（静态绑定）。

## 变量类型与初始化对比

**结论**：实例变量和类变量（静态变量）有默认值；局部变量**没有默认值**，必须显式初始化后才能使用；final 变量必须赋值一次，之后不可变。

**各类变量特性**：
- **实例变量**（非 static 成员变量）：定义在类中方法外，有默认值，每个对象独立存储。
- **类变量**（static 成员变量）：定义在类中方法外，类加载时初始化，有默认值，所有实例共享。
- **局部变量**：定义在方法或代码块内，**无默认值**，必须在首次使用前显式赋值。
- **final 变量**：一经赋值不可修改。成员 final 可在声明时或构造器中赋值（若未赋初值）；局部 final 在使用前必须赋值一次。

**默认值速查**：
- 数值类型（int, long, float, double 等）：`0` / `0.0`
- 布尔类型（boolean）：`false`
- 引用类型（String, Object, 数组等）：`null`
- char：`'\u0000'`（空字符）

**易错点**：
- 成员变量（实例/静态）不初始化不会报错，编译器赋默认值。
- 局部变量不初始化直接使用会导致**编译错误**，而非运行时异常。
- `final` 修饰的成员变量若未在声明时赋值，必须在所有构造器中完成赋值（或构造器链中确保赋值）。
